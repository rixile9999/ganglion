# 인터페이스 개선안
## 인터페이스
웹기반 인터페이스 제공
- 필요 컴포넌트
    0. 로딩할 모델 선택 컴포넌트 : 서로 다른 명세의 스키마에 서로 다른 모델이 대응할 가능성도 있으므로 모델을 선택할수도 있어야 함.
    1. 현재 모델과 대응되는 tool calling(mcp 명세) 오리지널 명세 및 action IR을 볼 수 있는 뷰
    2. 채팅 창: 사용자의 텍스트 입력을 받아 최종결과(툴콜링 코드)를 보여주면 됨.
        - 가능하다면 복잡한 지시에 대응하여 순서에 맞게 여러개의 툴콜링 코드를 만들어내는 결과도 보여주었으면 함.

# 분석 및 피드백 개선
## RLHF
채팅창에서 입력하여 나온 결과에 대하여 사람의 확인(맞았는지, 틀렸는지, 틀렸다면 expected result는 무엇이었는지 등등)을 입력받는 UI를 추가하여 모델 학습용 데이터로 써먹음

## 검증 규칙 확장, 축소
사후적으로 모델이 자주 틀리는 패턴에 대하여 추론 결과 수정 규칙 확장 여부를 판단, 결정하는 기능.
피드백 과정으로 모델 개선 학습이후 안틀리는 결과에 대해서는 수정 규칙을 축소시킬 수도 있음.

# 로그 분석 페이지
모델이 틀리는 패턴에 대한 분석  결과를 리포트 해주는 페이지
잘못된 추론 통계분석, 후보정에서 프로세스 결과 통계분석, 피드백 루프(모델 개선 학습) 단계에서 일어난 학습 변경점 등등을 보여줌. 단일페이지로 만들지 말고 각 피드백 루프 당시 모델의 상태 분석, 데이터 정보를 다 볼 수 있으면 함. 필요할 경우 세부적인 로그를 볼 수 있고 틀린결과, 달라진 결과 등등만 업데이트하여 볼 수 있는 필터도 있었으면 좋겠음.
