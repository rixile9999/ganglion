02 · 스펙이 바뀌면 어떤 경로로 움직일까?

설계 동작 예시입니다. 실제 실험 결과나 실행 상태가 아닙니다.

    요구사항과 해결책을 분리

    DomainSpec은 지켜야 할 의미입니다. 모델과 보정 규칙은 그 의미를 구현하는 버전별 후보입니다.

    빠른 갱신과 학습 갱신을 연결

    재사용·규칙으로 해결되는지 확인하고, 필요하면 SFT·RL·증류에 예산을 배분합니다. 순서는 원인에 따라 달라집니다.

    측정한 패키지를 그대로 배포

    가중치·IR·규칙·실행 설정을 묶어 평가합니다. 양자화·재시도·대체 모델 비용까지 포함합니다.

    03 · 장치에서 요청 하나가 처리되는 과정

    팩토리는 밖에서 최적화하고, 런타임은 고정된 버전을 실행합니다.
    요청 + 상태→버전 고정→작은 모델→파싱 · 보정→재검증→도구 실행→결과 기록

    실행 전 검증 실패 → 정해진 예산 안에서 재시도·질문·거부·호환 대체 경로를 선택합니다.
    실행 후 결과가 불명확하면 상태를 조회합니다. shadow 비교는 실제 도구를 중복 실행하지 않습니다.
